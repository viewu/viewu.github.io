# 学习的单位，从一门课程变成一个问题

## 01 一打开视频就困，切回文字反而清醒

前段时间，我在学习时遇到一个很明显的变化。

我原本在阅读文字资料，碰到一个知识点不太明白，就去搜索相关视频。视频刚开始播放没多久，我就开始犯困，注意力涣散。于是我马上关掉视频，重新切回文字，困意就消失了。

这让我开始留意自己使用不同媒介时的状态。

读文字的时候，我需要不断参与。哪里没看懂，我会停下来；前后逻辑没接上，我会回看；遇到已经了解的内容，我可以直接跳过。阅读速度也掌握在自己手里。

<img src="/images/learning-unit-from-course-to-question/2.webp" style="zoom: 50%;" />

视频则按照讲解者设定的速度往前走。即使某一段已经听懂了，我也要等他讲完；某一处没有跟上，视频仍然会继续播放，没有给自己停下来思考的时间。只要内容密度稍低，我就很容易从学习者变成一个坐在屏幕前的观众，看似在进行视频学习，其实大脑根本就没在参与信息的处理。

这段经历让我对流行的速成课产生了一个疑问。

一门课程可以用两个小时讲完某个领域的基础知识。可这两个小时究竟压缩了什么？它真的缩短了学习时间，还是只缩短了别人替我筛选、整理和讲解知识的时间？

## 02 算法思想听懂了，代码还是写不出来

我以前学算法课程时，很依赖视频。

上课的时候，老师从算法思想讲到代码实现，我大多都能听懂。老师定义一个变量，我觉得合理；老师写出一层循环，我也能理解；老师把整段代码跑通，我甚至会觉得自己已经掌握了。

关掉视频以后，情况完全变了。

算法思想还能大致说出来，我却很难独立写出完整代码。变量应该怎样定义、分别保存什么状态，经常想不清楚。循环逻辑容易绕进去，迭代条件和边界条件也不明确。有时思路勉强写出来了，还会卡在语法错误上。

网上有一句很形象的话：眼睛会了，手没会。

<img src="/images/learning-unit-from-course-to-question/3.webp" style="zoom:50%;" />

老师讲解时，很多决定已经替学生做好了。用哪些变量表达状态，循环从哪里开始、到哪里结束，每轮更新什么，什么情况下提前退出，数组为空或者下标越界怎么处理，这些步骤在一份完成度很高的讲解里依次出现，看起来十分顺畅。

但是自己动手时，每一个决定都要重新生成。只要其中一处含糊，代码就写不下去。

2018 年发表在 *Psychological Science* 的一项研究做了六个实验。参与者反复观看别人完成投飞镖、跳 moonwalk 和玩在线游戏等任务后，对自己能力的判断提高了，实际表现却没有随观看次数一起提高。研究者把这种现象称为观看带来的**“技能获得错觉”**。这个实验研究的任务和编程不同，但它解释了一个很相似的落差：**看清别人做了哪些步骤，并不会自动带来亲自执行这些步骤的能力。**

达到“会了”至少隔着几层距离。

听老师讲时能够跟上，是一层。

离开材料还能说出算法思想，又是一层。

把思想拆成变量、状态和控制流程，独立写出代码，根据报错修改，再把方法迁移到一道相似的新题里，后面还有很长一段。

我以前常常在第一层产生已经学会的感觉。视频进度条继续向前，课程也一节一节被标记为完成。**可视频课程的进度，并不等于我的能力进度。**

## 03 速成课压缩了路径，练习仍然要自己完成

我现在依然承认优质速成课的价值。

进入一个陌生领域时，最容易浪费时间的地方之一，就是不知道应该学什么，也不知道按照什么顺序学。好的课程替学习者筛选资料、搭好框架、安排顺序，再用例子帮助建立最初的理解。这些工作当然值得付费。

问题出在“速成”两个字容易制造另一种期待。

老师可以压缩探索路径，却无法替学生完成理解、提取、应用和纠错。算法的知识地图可以在两个小时里讲完，但是实际动手时，把算法写成代码的犹豫、报错和调试仍然会发生。

<img src="/images/learning-unit-from-course-to-question/4.webp" style="zoom:50%;" />

学习研究会区分“再次接触材料”和“主动从记忆中提取材料”。2008 年发表在 *Science* 的一项实验让大学生学习 40 组外语词对（斯瓦希里语—英语）。某个词对被正确回忆一次后，研究者发现，后续继续呈现并复习这个词对，并没有提高一周后的回忆成绩；继续要求学生根据提示调出答案，则明显改善了长期保持。这个结论只适用于该实验中的词对学习，不能直接替代编程练习，也不能简单概括成“重复阅读没有用”。但它给我的提醒很具体：**对一段材料越来越熟悉，和离开材料以后还能不能调用，是两个不同的问题。**

**速成课最容易提供的是熟悉感。**

老师说到一个概念，我见过。画出一张流程图，我看得懂。敲出一段代码，我也知道每一行大概在做什么。这些感受都是真的，但它们只能说明我能够**识别眼前的内容。**

关掉资料以后能不能复述，打开空白编辑器能不能开始，遇到报错能不能继续排查，换一个问题能不能重新组织知识，这些结果才会暴露学习发生到了哪一步。

**即使信息被讲完了，能力还需要在使用中形成。**

## 04 我开始直接查官方文档

后来，我逐渐减少了视频在学习中的比例。

我通常先搜索文字资料。遇到实在难以理解的地方，才会找相关视频，听一听别人怎样解释，或者观察某个动态过程。

有一次，我在写 Markdown 文档时碰到一个很小的语法问题。脑子里刚闪过“找个视频看看”的想法，我马上改成了直接查看 Markdown 官方文档。通过搜索定位到对应语法，看完说明和示例以后，我很快解决了问题。

这件小事让我很清楚地感到，自己的学习方式稍微变了一点。

以前我觉得官方文档晦涩难懂，也不太愿意接近。现在我越来越能感受到官方文档的含金量。它的信息密度高，规则和示例放在一起，又可以围绕当前问题直接检索。我不需要等一个人从基础概念讲到自己需要的那一页。

发生变化的还有一点：**我不再总想着把全部内容学完，再去解决实际问题。**

**以前的完美主义很容易把学习拉成一条很长的准备期。**想做一件事，先觉得自己基础不够；为了补基础，找来一门完整课程；打开课程，又觉得应该从第一节开始。**时间不断花在准备上，最初的问题迟迟没有推进。**

<img src="/images/learning-unit-from-course-to-question/5.webp" style="zoom:50%;" />

现在，我会先问自己缺少哪一小段知识。能够帮助我解决当前问题的部分，我就先学这一部分，然后立刻放回原来的任务里验证。

Markdown 能不能正常显示，代码能不能运行，问题有没有解决，都会给出直接反馈。

**我的学习单位逐渐从一门课程，变成了一个正在解决的问题。**

## 05 问题连成一条链时，我再回去补系统知识

按需学习也有明显的边界。

有些问题相对独立。一个 Markdown 语法不会，查到规则、用进文档，当前问题就解决了。为此从头学完一门 Markdown 课程，投入和产出并不匹配。

另一些问题依赖很多前置知识。

我想解决问题 A，却发现它依赖问题 B；继续追下去，问题 B 又依赖问题 C，而我对 B 和 C 都不熟悉。问题由一个点变成一条依赖链。沿着这条链追根溯源，我会逐渐看见自己缺少的是哪一片基础知识。

这时，系统学习就有了明确范围。

**我不需要因为一个小问题，把整个领域从头学到尾；也不能永远只查零散答案，让相同的前置缺口反复出现。孤立问题可以就地解决。多个问题指向同一组前置知识时，再集中补上这一部分。**

<img src="/images/learning-unit-from-course-to-question/6.webp" style="zoom:50%;" />

这也让我重新理解了攀岩时想到的“**学习体能**”。

我第二次攀岩时，因为平时有健身习惯，身体力量和控制能力让我很快超过了去过好几次的朋友。攀岩技巧仍然需要专门练习，但基础体能给了我更高的起点。

学习也有类似的基础，其实就是一些学习“如何学习”的**元认知能力**。能够集中注意力，读懂密度较高的文字，准确描述问题，检索一手资料，把复杂问题拆开，发现前置依赖，忍受暂时不会和反复报错，再通过使用结果修正理解，这些能力不会局限在某一门课程里，相当于学习的一些底层逻辑，我将其类比为“学习体能”，学习体能好的人，学习其他陌生知识的时候也大概率能够更快地上手。

它们决定了一个人进入陌生领域以后，能不能逐渐摆脱对完整讲解的依赖。

现在的我仍然会看视频。需要观察动作、界面变化或者某个动态过程时，视频能够提供文字很难呈现的信息。遇到一种完全陌生的观点，我也愿意听别人怎样讲。

只是视频不再是默认入口。文字和文档承担了主要学习过程，视频负责补充少数难以理解的环节。

我也不再用“今天看完了几节课”判断学习效率。关掉资料以后，我能不能自己写出来、解释清楚、发现错误，最初的问题有没有向前推进，这些结果更接近我现在理解的学习。

课程可以替我整理知识。

从看懂走到会用，仍然要由我亲自完成。
